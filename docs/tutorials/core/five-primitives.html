Core tutorial 1

Start with the five primitives

ENTITY is easiest to understand when you refuse to collapse unlike things into one record. An object is not an authority. A right is not an event. Evidence is not value. The Universal Transaction Fabric keeps those concerns separate and connectable.

ENTITY → AUTHORITY → RIGHT → EVENT → VALUE

1. Create the controlling Entity

Create or load an ENTITY identity with EntityIdentityVault. The identity signs later state transitions; it is not the same thing as the governed object.

identity = EntityIdentityVault(STATE)
controller = identity.create("Example Organization", "organization")
controller_id = controller["entity_id"]

2. Register a governed object

The Universal Transaction Fabric supports object classes such as PERSON, ORGANIZATION, AI_AGENT, DATASET, DOCUMENT, MODEL, SOFTWARE, API, DEVICE, VEHICLE, BUILDING, RESEARCH, DIGITAL_TWIN, FINANCIAL_INSTRUMENT and PHYSICAL_ASSET.

fabric = UniversalTransactionFabric(STATE, identity)
obj = fabric.register_object(
    controller_id,
    "DATASET",
    "Boundary Weather Dataset",
    descriptor={"source":"sensor-network", "region":"BC"},
    content_sha256=CONTENT_SHA256,
)
object_id = obj["object_id"]

The returned object says who controls the object record and binds a content commitment. It deliberately states that custody is not authority.

3. Keep the other primitives separate

PrimitiveQuestionExample
ENTITYWhat persistent governed actor/object exists?The dataset object.
AUTHORITYWho may act for whom or on what subject?An operator may LICENSE the dataset.
RIGHTWhat may a grantee do with the object?A researcher may READ and TRAIN for a stated purpose.
EVENTWhat happened?Use was authorized, a derivation was created, an attestation was issued.
VALUEWhat economic state is asserted?POTENTIAL, OFFER, CONTRACTED, ACCRUED, SETTLED or REALIZED.

4. Verify the design boundary

Do not encode “the cloud account owns the dataset,” “the database operator may license it,” or “because it was ingested it belongs to ENTITY.” The fabric intentionally separates hosting, custody and transport from authority.

Checkpoint: you should now be able to point at one governed object and identify five separate questions around it: existence, authority, rights, events and value.

About ENTITY

Canadian-designed open infrastructure.

ENTITY is designed and stewarded by Blackmore Technology Group Limited as open infrastructure for persistent identity, authority, information, rights, evidence, governed events, value, recovery and continuity.

Open source

The core ENTITY repository is published under Apache-2.0 so outside developers and organizations can inspect, test, reproduce, fork and independently implement public protocol material.

Canonical origin

Origin is provenance—not automatic ownership.

Shawn Blackmore → Blackmore Technology Group → ENTITY

The canonical lineage preserves the project’s origin and stewardship history. Under the current canonical-status rules, replacing the root originator, replacing BTG as steward or removing the verified origin lineage means a derivative should not be described as canonical ENTITY.

Canonical origin does not automatically give BTG ownership of downstream user assets, datasets, derivatives or payments. It does not create an automatic protocol royalty or transfer upstream ownership merely because data is registered, ingested, mirrored, verified or processed through ENTITY.
What ENTITY is trying to solve

Provider-independent trust without collapsing semantics.

Persistent authority

Digital identity and delegated authority should remain understandable even when the application, infrastructure provider or custodian changes.

Governed information

Data lineage, rights, evidence, derivation and usage should remain machine-verifiable without pretending provenance alone establishes truth or legal ownership.

AI boundaries

Reasoning systems should operate inside explicit authority and evidence boundaries rather than becoming the source of permission, ownership or economic rights.

Development model

Public engineering, explicit evidence boundaries.

  • public core repository
  • public release history
  • sealed conformance material
  • six BTG-controlled language baselines
  • external verification challenges
  • independent implementation path
  • security and qualification targets
  • public documentation and research resources
BTG-controlled test results are engineering evidence. They are not represented as unrelated third-party validation. Outside reproduction, independent implementation, security review and institutional pilots remain separate evidence classes.

VALUE

Layer boundary: this page explains later/current runtime economic-state semantics. It is not an additional Protocol 1.0 clean-room requirement.

VALUE is runtime economic-state information representing a bounded economic consequence under explicit terms and evidence.

State distinction

The runtime distinguishes states such as potential, offer, contracted, accrued, settled and realized so an estimate, offer or provenance contribution is not silently represented as cash, settlement finality or accounting fair value.

Evidence requirement

Provenance or contribution can exist with zero monetary value. A price, royalty, revenue share or settlement should be tied to the contract, instrument, market or settlement evidence that supports that state.

Market evidence

Offers and bids are evidence of willingness at a point in time; completed transactions can provide stronger transaction evidence; settled cash/entitlements are a different state again. None automatically determines corporate valuation.

Economic boundary

The current BTDU architecture contract records automatic_protocol_royalty_bps = 0. BTG or any originator participates economically only through explicit rights, contracts, services, positions or other applicable terms. Protocol origin, provenance, ingestion or repository custody do not themselves create automatic economic entitlement.

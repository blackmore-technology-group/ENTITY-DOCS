GitHub Evidence Bridge

GitHub supplies useful public evidence—commits, trees, tags, releases, workflow results, reviews and artifacts—but ENTITY treats each as evidence with a specific scope, not as sovereign authority.

Version boundary: current ENTITY runtime = v3.4.3. BTDU repository ingestion remains component version 3.4.2 unchanged. Historical GitHub evidence should retain the exact tag/commit against which it was captured.

Useful evidence

  • Exact merge/head commit and Git tree.
  • Signed annotated tag and published release.
  • Release assets and SHA-256 digests.
  • Workflow/check conclusions and logs.
  • Pull-request review/change history and maintainer acceptance.
  • Issue state/closure evidence where relevant.

Binding into ENTITY

Capture immutable identifiers/hashes and ingest them as evidence/provenance references. In the current v3.4.3 runtime, the unchanged BTDU 3.4.2 repository-ingestion component supports a pinned git://owner/repo@commit provenance reference and records commit/tree/aggregate/root information.

Release evidence

For current ENTITY release evidence, the signed v3.4.3 tag resolves to commit 528b70aabd05b1e930b77e4933f157731e47274f. For older campaigns, preserve their actual historical commit/tag rather than replacing it with the current release label.

Boundary

GitHub hosting does not become authority over ENTITY users. A workflow pass proves the workflow result in that environment; it does not automatically prove unrelated independent validation, external deployment fitness, legal title, payment or settlement.

Contribution evidence

Upstream PR acceptance can be recorded as external technical adoption evidence. It remains distinct from the contributor's rights context and from commercial settlement. This is why the public contribution ledger keeps technical acceptance and payment state separate.

BTDU — Blackmore Technology Data Universe

BTDU means Blackmore Technology Data Universe. It is a governed information-substrate component used by the current ENTITY runtime architecture; it is not part of the normative ENTITY Protocol 1.0 clean-room conformance target.

What BTDU is

The published BTDU architecture contract describes BTDU as a governed universal information substrate. The current public ENTITY documentation describes it as an atomic/bonded information architecture in which reusable atoms, bonds and compounds can be connected to ENTITY provenance, authority, rights and economic state.

Atoms → Bonds → Compounds → Governed Objects → Provenance / Rights / Economic Lineage

BTDU is a representation model for structured, semantic and relational information. It is not presented as generic raw-file compression.

Version boundary

ENTITY v3.4.3 is the current supported runtime. The BTDU component remains version 3.4.2 unchanged inside that runtime release.

Protocol 1.0 boundary

If you are implementing ENTITY Protocol 1.0 from the sealed conformance kit, you do not need to implement BTDU, ADAM or NIKI.

The Protocol 1.0 clean-room challenge is defined by the sealed conformance kit: the interoperability profile, canonicalization/cryptography rules, schemas, implementation interface, vectors and pass criteria. The clean-room rules expressly exclude BTG runtime internals such as ADAM and NIKI from the implementation path.

The BTDU example on the AUTHORITY page is therefore only an illustration of how ENTITY authority can be applied by a current BTG runtime component. It is not an additional Protocol 1.0 requirement.

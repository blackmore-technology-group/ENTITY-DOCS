Identity first

A wallet does not silently turn a device account into a person.

INSTALL → CREATE / ADOPT ENTITY IDENTITY → CLAIM .entity ALIAS → OPTIONAL ORGANIZATION → BIND DEVICE ENTITY → SIGNING CHALLENGE → WALLET

Human-readable aliases

Public .entity names improve usability, but immutable Entity IDs and signatures remain authoritative.

Separate device identity

Device information can create/bind a Device ENTITY. It does not silently establish human or organization lineage.

Dynamic lineage

The wallet header resolves the active user's real lineage rather than hard-coding BTG structure into every installation.

Asset and instrument separation

A DCO can exist without a ticker, price or listing.

DCO → SIGNED ASSET DISCLOSURE → RIGHTS / GLOBAL PASSPORTS → OPTIONAL ECONOMIC INSTRUMENT → OPTIONAL LISTING

Digital Assets

DCO holdings show immutable object identity, provenance, passports, domain context and disclosure state. An asset without an instrument displays NO TICKER.

Issuer-scoped instruments

Economic instruments receive issuer-scoped market identifiers and rights classes only after explicit issuance.

Information sheets

Listings bind buyer-facing signed asset disclosures and canonical passport/rights facts instead of presenting an unexplained ticker.

Rights Passport drives issuance

The wallet cannot invent rights the asset does not have.

The active Rights Passport defines the maximum action set. An economic instrument may select only a subset of current ALLOW actions. Prohibited or non-directly-issuable actions are not selectable, and the canonical market registry revalidates the subset before creation.

Example: the qualified BIRFR-1 Rights Passport exposes BENCHMARK, CERTIFY, COMPUTE, DERIVE, EVALUATE, FINE_TUNE, INFER, OEM_DEPLOY and TRAIN. It does not expose COMMERCIALIZE, so the wallet does not offer COMMERCIALIZE for that DCO. Selecting TRAIN can suggest BIRFR1-TRN.

Qualification

Current wallet evidence is separate from the immutable v3.4.3 tag.

The immutable v3.4.3 tag remains the bounded Issue #28 remediation release. The wallet described here is post-tag main-branch application-layer evolution. The final focused wallet/economy/lineage/onboarding/global-passport suite passed 91/91 before the final Windows rebuild.

Implementation baseline: 212ee56d34aee578e6df701ef9f9a675661b7162. The locally installed Windows EXE built from that baseline had SHA-256 4F360D9F2C9DC51600B2C5D76FAA09364ADEF6762255D17F4DC528BDF3C069DD. GitHub Actions artifacts are rebuilt on hosted runners and therefore have their own hashes.
Claim boundary: a wallet UI does not create ownership, objective truth, legal classification or economic value. Domain profiles do not mint Rights-Passport authority. Quotes are not settlement. A ticker is not intrinsic value. The iOS inspection client is not represented as a native authority engine.

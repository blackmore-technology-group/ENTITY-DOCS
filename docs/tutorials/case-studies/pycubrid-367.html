PyCUBRID #367 - validate timeouts before resource acquisition

A real external engineering campaign: reproduce invalid timeout behavior, add a shared sync/async pre-transport validation control, verify the fix, submit upstream PR #576, then preserve the resulting ENTITY lineage.

Evidence boundary: This page is generated from command/output records and sealed campaign evidence. Upstream acceptance, payment and market value are stated only when separately evidenced.
ISSUE -> PRE-CODE ENTITY ANCHOR -> RED TEST -> FIX -> GREEN VALIDATION -> UPSTREAM PR -> ENTITY LINEAGE

The defect

Invalid negative, NaN and infinite timeout values reached connection setup instead of failing before transport/resource acquisition.

The engineering change

A shared validator was added to common connection initialization so sync and async paths reject invalid timeout values before socket acquisition while preserving None, zero and finite positive values.

Validation

Original red regression: 20 failed / 10 passed. After fix: 30/30 focused tests passed. Broad offline validation: 2980 passed, 10 skipped, 11 failures reproduced identically on untouched upstream SHA; coverage 97.67%.

Partnerships

Start with one bounded problem.

ENTITY partnerships are built around small, falsifiable experiments. The goal is not to ask an organization to adopt an entire platform; it is to identify one trust, rights, provenance, authority or recovery problem and produce evidence that the organization can control.

Pilot definitionsIndependent qualification
Four flagship programs

ENTITY Agent Authority Lab

AI agent → persistent identity → delegated authority → permitted data/action → governed transition → evidence/provenance → revocation/recovery.

Question: can agent actions remain bounded by explicit authority rather than inferred from model output?

Sovereign Data Rights Lab

Apply machine-readable inspect/query/train/derive/redistribute/commercialize/sublicense rights to a real dataset and test provenance, usage and economic consequences across boundaries.

Portable Organizational Authority Lab

External verified credential → ENTITY persistent identity → organizational role → delegated authority → action → provenance → revocation → portable recovery.

ENTITY should not replace the credential issuer.

Independent BTDU Qualification

University or researcher controls the workload, comparison systems, methodology and conclusions. BTG supplies code, evidence and falsifiable hypotheses.

Where ENTITY can intersect

Integrate with existing ecosystems instead of pretending they do not exist.

Standards & digital trust

Identity, credentials, authorization, provenance and policy mapping with standards bodies and technical communities.

Agentic AI governance

Bounded machine authority, revocation, evidence, deterministic state transition and recovery around AI-agent actions.

Sovereign data & data spaces

Rights-bearing data, portable provenance, governed derivation and provider-independent recovery within existing data ecosystems.

Organizational trust

Use external credentials and organizational facts as inputs without converting ENTITY into the issuing authority.

Independent research

Security review, formal methods, interoperability, reproducibility and BTDU performance qualification.

Economic infrastructure

Rights instruments, usage events, receipts and bounded settlement/entitlement models where external legal/payment evidence remains distinct.

Partner conversion path

From conversation to external evidence.

20-second thesis → institution-specific case → 2-page brief → technical evidence room → pilot charter → external result

Discovery

Identify the problem the organization already owns and where ENTITY intersects without replacing its existing standards or infrastructure.

Technical workshop

Define one falsifiable question, test inputs, authority/evidence boundaries and what failure would look like.

Pilot charter

Set scope, owners, environment, success/failure evidence, IP/security boundaries and publication expectations before implementation begins.

What BTG is not asking for
A conversation, working-group participation, pilot, research review or editorial mention is not treated as endorsement. ENTITY does not ask standards organizations to validate marketing claims, and it does not present BTG-controlled evidence as independent evidence.
Begin

Choose the smallest experiment that matters.

The public partnership materials include specific pilot questions, external qualification modes and the current evidence boundary. Organizations can begin by reading those materials or opening a focused GitHub issue for a technical question.

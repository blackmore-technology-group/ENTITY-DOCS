# ENTITY Documentation Portal

Public operator, developer, protocol, market, economic, security, recovery, evidence, domain, version and generated-reference documentation for **ENTITY**.

## What ENTITY is

ENTITY v3.4.3 is a provider-independent **digital authority, information, evidence, market, economic and recovery operating fabric** from Blackmore Technology Group Limited.

Sovereignty is an important system invariant: hosting, custody, routing, storage or venue operation do not automatically become authority. But sovereignty is **not** the whole product.

The runtime is organized around five primitives:

```text
ENTITY → AUTHORITY → RIGHT → EVENT → VALUE
```

From those primitives, the implementation composes persistent identities/objects, delegated authority, machine-readable rights, governed information, causal provenance, evidence states, market execution, economic participation, settlement evidence and provider-independent recovery.

### Implemented economic / market surface

ENTITY includes first-class support for:

- venues;

- RFQs, quotes and acceptances;
- trades and clearing;
- entitlements and usage;
- surveillance and cancellations;
- revenue rules and versioned rule sets;
- authorized settlement verifiers;
- payment attestations;
- treasuries, reserves and participation policies;
- market-state recovery.

Market lifecycle:

```text
DCO → INSTRUMENT → LISTING → DISCLOSURE → ORDER / RFQ / AUCTION
→ PRICE DISCOVERY → TRADE → CLEARING → SETTLEMENT → ENTITLEMENT
→ USAGE → DERIVED OUTPUT → ECONOMIC CONSEQUENCE
```

Execution models include `ORDER_BOOK`, `CALL_AUCTION` and `RFQ`.

Instrument classes include `SPOT_LICENSE`, `SUBSCRIPTION`, `COMPUTE_TO_DATA`, `PROCUREMENT`, `CONTRIBUTION` and `SECONDARY_LICENSE`.

ENTITY does not require artificial scarcity of information bytes. Economic scarcity can exist in bounded rights, entitlement, capacity, duration, jurisdiction, usage quantity, derivation, participation and transferability.

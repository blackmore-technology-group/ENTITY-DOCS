Upgrade & Version Control

ENTITY releases are immutable semantic targets. Upgrade by moving to a new qualified release, not by editing the old tag in place.

Current status

v3.4.2 is the sole current supported canonical release. v3.4.1 is explicitly SUPERSEDED/unsupported for current deployment and retained as historical provenance.

Upgrade procedure

  1. Back up/export current sovereign state and record roots.
  2. Pin and verify the target release/tag.
  3. Read migration/supersession notes.
  4. Run regression/qualification in a non-production copy.
  5. Apply required migration while preserving historical signed semantics.
  6. Verify identities, rights, evidence and passports.
  7. Run recovery/export smoke test.
  8. Promote and retain rollback evidence.

Never

Never rewrite historical records so they appear to have been issued under new semantics. Explicit supersession/migration is required.

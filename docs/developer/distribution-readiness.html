What the package-smoke gates prove

The smoke gates are deliberately separate from protocol conformance. They test whether the distribution artifact itself can be packaged, resolved, built, installed or executed in the way expected for that ecosystem while the existing clean-room campaign remains green. This prevents a package from being described as registry-ready merely because the source tests pass.

What remains outside BTG control

Registry accounts, namespace ownership, first-publication rules, trusted-publisher policies and third-party package indexes impose external requirements. Those steps are recorded as gates rather than silently treated as complete. Until a registry or index actually exposes a package, this page describes it as qualified or publication-ready—not published.

Independent evidence remains a separate lane

The six language baselines help outsiders reproduce behavior and lower implementation friction. The stronger evidence event remains an unrelated engineer, institution or research group controlling its own implementation, methodology and conclusions. See Clean-Room Implementation and Independent Qualification.

Yomihon #848 - contract-declared status truthfulness

A real external engineering campaign: make reader-visible status wording derive from the canonical vault contract instead of duplicated presentation-layer policy.

Evidence boundary: At evidence capture, PR #852 was open and GitHub workflow approval was pending. Upstream acceptance, payment and market value are not claimed.
ISSUE -> PRE-CODE ENTITY ANCHOR -> RED TEST -> FIX -> MUTATION PROOF -> UPSTREAM PR -> ENTITY LINEAGE -> DCO

The defect

With no_frontmatter_is_legal = false, the page correctly reported missing frontmatter as a contract violation while the status face still told the reader that no frontmatter was legal.

The engineering change

The page now receives whether the loaded contract requires frontmatter, uses that canonical declaration to choose bilingual status wording, and keeps the existing legal wording only when the contract actually permits missing frontmatter.

Validation

The new page test was observed red against the original behavior, then green after the fix. A deliberate mutation removing the contract-driven branch made the same test red again. Focused Go test, go vet, formatting and diff checks passed; the broader Windows comparison introduced zero new failures versus the exact upstream baseline.

What the package-smoke gates prove

The smoke gates are deliberately separate from protocol conformance. They test whether the distribution artifact itself can be packaged, resolved, built, installed or executed as expected for that ecosystem while the recorded clean-room campaign remains green. This prevents a package from being described as registry-ready merely because source tests pass.

What remains outside BTG control

Registry accounts, namespace ownership, first-publication rules, trusted-publisher policies and third-party package indexes impose external requirements. Those steps are recorded as gates rather than silently treated as complete. Until a registry or index actually exposes a package, describe it as qualified/publication-ready rather than published.

Relationship to v3.4.3

The v3.4.3 release carries forward compiled Rust clean-room/conformance qualification from v3.4.2 as inherited unchanged-scope evidence. That does not change these package versions to 3.4.3 and does not imply every language lane was re-executed against v3.4.3.

Independent evidence remains a separate lane

The six language baselines help outsiders reproduce behavior and lower implementation friction. Stronger evidence remains an unrelated engineer, institution or research group controlling its own implementation, methodology and conclusions. See Clean-Room Implementation and Independent Qualification.

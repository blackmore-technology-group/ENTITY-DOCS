Evidence ladder

Not every pass proves the same thing.

1 · BTG-controlled qualification

Tests executed against code and campaigns controlled by BTG. Useful engineering evidence, but not unrelated validation.

2 · External reproduction

An unrelated person independently runs a published BTG baseline and reports their environment, results and hashes.

3 · Independent implementation

An unrelated implementer builds from public specification/conformance material in a repository and architecture they control.

4 · Independent security review

An outside security researcher or assessor controls the test method and reports vulnerabilities, assumptions and exclusions.

5 · Standards interoperability

ENTITY exchanges or maps behavior with an established external implementation or standard at a clearly defined boundary.

6 · Institutional pilot

An organization uses ENTITY against a real bounded problem and controls evidence from its own environment and requirements.

What this does not prove

The contributor reproduced a BTG-controlled implementation. That is meaningful portability/reproducibility evidence, but it is not a separately designed ENTITY implementation and does not establish full external interoperability.

The next stronger test is a clean-room classifier or protocol implementation owned and authored outside BTG.

Security vulnerability

Do not post exploit details, private keys, production data or sensitive vulnerability material in a public issue. Follow the repository security policy and private-reporting path.

Security policy →
Please do not send production credentials, recovery keys, private signer material, personal data or unredacted security-sensitive evidence through public GitHub issues.
Press & project announcements

Use evidence, not promotional claims.

For technical publications, newsletters or open-source communities, the most useful entry points are the current release, external verification challenge, developer hub and independently reproducible evidence. Editorial interest is not represented as endorsement.

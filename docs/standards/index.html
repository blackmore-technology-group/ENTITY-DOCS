Standards & Interoperability

Open technical material for standards review

ENTITY v3.4.2 is an open-source protocol/reference implementation for persistent identity, delegated authority, provenance, rights, governed events, portable recovery and explicit economic state. This section extracts the interoperability problem and protocol boundaries into material that standards engineers can review without treating ENTITY as endorsed by any standards body.

Claim boundary: nothing in this section claims IETF, W3C, DIF or other standards-body approval, adoption, certification or conformance. The working draft below is pre-submission discussion material.

Pre-submission authority/provenance draft

The first standards-facing draft focuses on the provider-neutral core: ENTITY → AUTHORITY → RIGHT → EVENT → VALUE, authority delegation, evidence versus authority, provenance, portable state, recovery and interoperability/conformance boundaries.

Why publish this before submission?

Review before positioning

Protocol engineers can challenge terminology, overlap, security assumptions and interoperability scope before BTG asks any standards body to process the document.

Separate mappings from conformance

ENTITY may map concepts to verifiable credentials, decentralized identifiers, authentication systems and provenance standards without claiming those systems confer ENTITY authority.

Reproducible implementation

The public source, v3.4.2 release, conformance material and external review issues remain the engineering evidence behind the discussion.

Open feedback

Reviewers can file bounded counterexamples or implementation findings directly against the public repository.

Useful review questions

  • Can an externally valid credential accidentally escalate into sovereign authority?
  • Can provenance be confused with ownership, truth or economic causality?
  • Are authority delegation and revocation semantics portable across providers?
  • Can independent implementations reproduce the same canonical decisions?
  • Does destructive recovery preserve identity rather than manufacture a replacement?

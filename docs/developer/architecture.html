Developer architecture · ENTITY v3.4.3

Complete Runtime Architecture

ENTITY is a governed digital-economic operating fabric. It combines persistent actors/objects, explicit authority, machine-readable rights, encrypted information, deterministic state, causal intelligence, market execution, economic participation, evidence-bound reality, provider-independent recovery, passports, standards adapters and industry packages.

Current version boundary: ENTITY v3.4.3 is the current supported runtime. The BTDU component remains 3.4.2 unchanged. v3.4.2 itself is immutable historical release evidence, not the current deployment label.

Five primitives

ENTITY → AUTHORITY → RIGHT → EVENT → VALUE

Everything else composes these primitives. ENTITY identifies persistent subjects/objects. AUTHORITY says who may act. RIGHT says what may be done. EVENT records attributable state transition/evidence. VALUE represents bounded economic consequence.

Authority and rights control plane

Persistent objects

People, organizations, AI agents, datasets, documents, models, software, APIs, devices, vehicles, buildings, research, digital twins, financial instruments and physical assets can be governed objects.

Delegated authority

Actions include ACT, SIGN, ACCESS_DATA, EXECUTE, PURCHASE, LICENSE, SETTLE, PUBLISH, RESOLVE, DELEGATE and CONTROL with explicit scope/expiry/revocation.

Rights

INSPECT, READ, COPY, DERIVE, TRAIN, INFER, EXECUTE, MODIFY, REDISTRIBUTE, COMMERCIALIZE, CONTROL and TRANSFER remain separate from authority and custody.

Information, state and reasoning

ENTITY AUTHORIZATION → BTDU GOVERNED INFORMATION → ADAM DETERMINISTIC STATE → NIKI BOUNDED REASONING

ENTITY remains authority/rights/economics. BTDU adds governed information topology and query indexes. ADAM executes deterministic atomic state. NIKI reasons over bounded projections/approved models. None of the lower layers may silently mint authority.

Economic architecture

DCO → INSTRUMENT → LISTING → DISCLOSURE → ORDER / RFQ / AUCTION → PRICE DISCOVERY → TRADE → CLEARING → SETTLEMENT → ENTITLEMENT → USAGE → DERIVED OUTPUT → ECONOMIC CONSEQUENCE

Exchange

ORDER_BOOK, CALL_AUCTION and RFQ execution across spot licences, subscriptions, compute-to-data, procurement, contributions and secondary licences.

Persistent market state

Venues, instruments, balances, listings, disclosures, orders, trades, clearing, entitlements, usage, surveillance, cancellations, revenue rules, settlement verifiers and payment attestations.

Participation

Treasuries, reserves, explicit primary/secondary/derivative participation, service revenue and obligations—without a token or automatic protocol tax.

Market recovery

The recovery layer snapshots logical exchange and participation tables, computes semantic hashes, carries identity manifests/controller attestations and restores into compatible clean state. This prevents a database file or cloud account from becoming the definition of the economy.

Verifiable reality and causal economics

Claims can be OBSERVED, ASSERTED, INFERRED, ATTESTED, EXTERNALLY_VERIFIED, ADJUDICATED, DISPUTED, REVOKED or UNKNOWN. The causal-economic graph connects source data, contributors, DCOs, rights, licences, usage, derived assets, products, transactions, revenue and settlement only through evidence-bearing acyclic edges.

Global infrastructure

Privacy & retention

Purpose-bound access with use caps/expiry/revocation; selective retention, destruction evidence and legal holds.

Federated/offline operation

Core/regional/edge/satellite/offline topologies, signed vector-clock checkpoints and fail-closed divergent partition handling.

Cryptographic agility

Suite registration, dual-sign transition, deprecation/retirement and downgrade resistance.

Institutional semantics

Versioned jurisdiction profiles and semantic registries with explicit crosswalks; policy evidence is not automatically legal truth.

Adoption and portability

Rights Passports and Global Passports bind existing authority/rights/evidence rather than replacing them. Custody connectors can point to AWS, Azure, Google Cloud, Snowflake, Databricks, PostgreSQL, SQL Server, local filesystems and HTTP APIs while keeping provider custody separate from authority. Standards adapters use explicit mappings for ODRL, W3C VC, DID, GAIA-X and IDS.

Architecture invariants

  • Identity is not an account.
  • Hosting/custody/venue operation is not authority.
  • Access is not ownership.
  • Provenance is not truth or legal title.
  • A model inference is not authority.
  • A trade is not verified external payment.
  • A payment attestation remains scoped evidence.
  • Economic observation is not accounting fair value.
  • Recovery preserves existing authority and rights; it must not manufacture new privilege.
  • Economic participation requires explicit terms; provenance does not retroactively create royalties.

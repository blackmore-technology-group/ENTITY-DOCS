Open-source provenance infrastructure

Data provenance without collapsing evidence into truth

ENTITY v3.4.2 models origin, custody, transformation, derivation, authority, rights and economic lineage as separately verifiable relationships.

What problem this addresses

Conventional provenance systems often record where data came from while leaving authority, rights, evidence quality and downstream use as separate application concerns. ENTITY treats those boundaries as first-class protocol semantics. A record can be cryptographically valid while still carrying an unproven external-world assertion. A source can be known without becoming the owner. A custodian can store bytes without gaining sovereign authority.

Core verification boundaries

  • Cryptographic verification: signatures, hashes and canonical payload integrity.
  • Protocol verification: whether an ENTITY transition obeys authority, rights and state rules.
  • External evidence: whether the real-world assertion is actually supported by the supplied evidence.

Keeping these layers separate is intended to prevent signature-to-truth escalation, provenance-to-ownership escalation and infrastructure-to-authority escalation.

BTDU integration

The Blackmore Technology Data Universe adds governed atomic/bonded topology. Exact bytes, source/controller/rights-holder relationships, repository manifests and economic nodes can be represented without allowing topology itself to create ownership or entitlement.

SOURCE → EVIDENCE → PROVENANCE → AUTHORITY / RIGHTS → EVENT → DERIVED STATE

Use cases

Relevant applications include AI training lineage, regulated records, software supply-chain evidence, research datasets, digital product passports, government records, industrial telemetry and rights-aware data exchange.

Verify it

ENTITY v3.4.2 is the current supported canonical release. The project publishes conformance material, recovery evidence, OpenSSF Scorecard results and bounded external qualification challenges.
